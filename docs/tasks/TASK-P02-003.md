## Objective and observable result

Produce the G02 capture evidence for the live runs and the 30-day pull from the captured data, without changing it:

- `python3 -I -B analyse.py live --run <run dir> --out <report.json>` reports, per pair: book-invalid time under DEC-071 and under the capture's own events, R-4 valid share, the longest valid stretch, R-3 recovery times; plus Q-5, T-3 per channel, pair and UTC day, T-5/T-6 counts and time under each flag, R-5 gzip size, frame-line integrity, segment hashes against the store index, and the store's own integrity.
- `python3 -I -B analyse.py rest --run <dir> --out <report.json>` reports each day's three calls (stored, first attempt, gaps, API errors) and the store's integrity.
- A run without `live-summary.jsonl` is reported as **provisional**, with its newest (open) segment skipped.

## Method (DEC-071 and the review fixes)

- **Invalid time per pair** is the union of (a) the capture's own intervals, from `book_invalid`/`disconnect` to the pair's next `book_valid`. A `parse_error` is attributed to the last frame received before it (the capture logs it right after handling that frame). If that frame is a book frame, the error also opens an interval for the frame's pairs until their next `book_valid`; otherwise it is only counted. This covers the PR #30 defect in the run-1 code (`5b69e7f`), where a parse error wrote no `book_invalid`; for that code the interval is an upper bound. Then (b) **DEC-071 silences**: consecutive frames more than 15 s apart give an interval from the earlier frame to the later one. A finished run's tail after its last frame counts too. Venue maintenance (`venue_status` = `maintenance`) is excluded (RC-11). R-4 = 1 − invalid / (window − maintenance), with and without the initial sync.
- **R-3:** from the first `disconnect` event after a valid book to the pair's next `book_valid`. That is the detection time; for a receive timeout it is up to 15 s after the last frame, and the DEC-071 gap already covers that stretch for R-4.
- **Q-5:** each `book_valid` must have a book snapshot frame for that pair with `recv_ns` between the pair's last invalidation and the `book_valid`.
- **T-3:** `recv_ns` − venue `timestamp` for book and trade updates, raw and plus the latest SNTP offset; 1 ms bins. `ingest − receive` is not measured (frames are journalled before parsing). Items older than 15 s on receipt are counted.
- **T-5/T-6:** time flagged from each successful sample to the next. Before the first sample counts only for T-6 intraday (DEC-067: `clock_offset_unknown` and `clock_abstain_intraday`). A sample older than 60 s triggers intraday abstention. The intraday figure is split by cause: before the first sample, offset over 1 s, stale sample. Run 1 queried SNTP every 60 s (`5b69e7f`, before DEC-066), so every gap between its samples is just over 60 s and adds a small stale slice.
- **Integrity and provenance:** every frame and event line parses; each closed segment's SHA-256 equals its index entry, and the entry carries SR-02/SA-03; index and journal lines are scanned without raising; every indexed object exists with its length and hash; the store opens with `read_only=True`. A summary whose end is more than 15 s before the last frame is flagged as inconsistent.
- **R-5:** gzip bytes per pair per day of frames received (first to last frame); the per-day figure over the whole window is reported beside it.
- **Limits:** a finished run's window is `ran_at_utc` (the command's start, a few ms before the capture's own start) plus `duration_s`, so events in the run's last few ms can fall outside it. Frame and event times use the wall clock (`time.time_ns`). A clock step just after a wake (the interruption page records −31 s) can shorten or lengthen a silence near it. This is not corrected.
