## Objective and observable result

Write `docs/evidence/P02/event-contract.md`, the documentation deliverable named in the P02 phase specification. It must contain, for every event type in the approved baseline:
- a field-by-field map from source field to meaning and provenance (P02 task 1);
- the raw-preservation rule, the normalized schema, versioning and ordering (task 2);
- the detection and disposition of gaps, duplicates, late events, disconnects, corrections and invalid records (task 3);
- the replay inputs and outputs, deterministic ordering, fixture selection and expected integrity checks (task 4).

Integrity fixtures are specified as documents, with expected results. No fixture data is committed.

**Sources in scope:**
- **Archived:** Binance Vision klines and trades (SA-01); Kraken OHLCVT archive and REST OHLC (SA-02); the context sources (SA-04 to SA-09).
- **Live, Conditional:** Kraken WebSocket v2 `book`, `trade` and `status` (SA-03). These types are specified so the contract is complete, but capture needs its own authorisation.
